# Imported character models (.glb)

This folder holds 3D bodies the game can load instead of its procedural models.
Everything here must be **original or explicitly approved** — no downloaded
character models.

| File | What it is | Origin |
|---|---|---|
| `test_dummy.glb` | Pipeline test mannequin (grey panel-textured body, orange joint markers, dark visor) | Generated by `node tools/make_test_glb.js`; original, made for this project (texture is a generated panel pattern) |
| `test_dummy.glb.js` | The same bytes as base64, so the game can load it when opened from `file://` | Generated by the same script |

## How a model is used

1. Check the file: `node tools/glb_check.js path/to/model.glb`. It parses the file with
   the game's reader, lists unsupported features, guesses the joint map (prints it ready
   to paste), checks the map's structure (hierarchy order, left/right sides, limb
   proportions), scale, feet on the ground, facing, skin weights and the budget below,
   then poses the model through every shared pose. Fix what it warns about.
   Options: `--id name`, `--height 1.85`, `--facing 180`, `--map jointmap.json`, `--json`.
2. Package it: add `--write-js`. That copies the `.glb` here and writes the `.glb.js`
   twin (base64, so double-clicking `index.html` still works without a server).
3. Add `<script src="assets/models/NAME.glb.js"></script>` to `index.html`
   (after `src/game/model_glb.js`).
4. In the character data: `model: { type: 'glb', asset: 'NAME', height: 1.85, jointMap: { ... } }`.
   `jointMap` can be left out when the bone names are conventional.
5. Look at it: `tools/viewer.html?char=ID&pose=stand`, then run `node tests/run-tests.js`.

The game keeps animating its own 17-joint rig and retargets every pose onto the
file's skeleton, so existing moves, poses, VFX origins and hit detection work
without new animation data.

## Production model requirements

**Format**
- glTF 2.0 binary (`.glb`), one file, buffers embedded. No external `.bin`.
- No required extensions (no Draco / meshopt compression, no KHR_texture_transform).
- **Textures:** base color textures embedded in the file (PNG or JPEG) are supported,
  with the file's sampler wrap/filter settings and the first UV set. They decode in the
  background; the body shows its color factors until then (a few milliseconds).
  Normal, emissive, occlusion and metal/roughness maps are ignored and reported — the
  game's cel shading does not use them. Keep images embedded, not as separate files.
- Triangles only. No morph targets (faces/expressions need them — not supported yet).

**Scale, orientation, pose**
- Y up, character faces **+Z**, its left hand on **+X** (glTF defaults; Blender's glTF
  exporter does this with "+Y Up"). If it faces −Z set `facing: Math.PI`.
- Any unit scale; the loader normalizes to `height` (default 1.85 m at character height 1).
- Bind pose: T-pose or A-pose both work. Feet flat on the ground, symmetrical.
- Apply all object transforms before export (no scaled armature object).

**Skeleton**
- One skin (armature). Bones for the 17 game joints, in this chain:
  hips → spine → chest → neck → head; chest → upper arm → forearm → hand (×2);
  hips → thigh → shin → foot (×2).
- Extra bones are fine (clavicles, extra spine, fingers, toes, twist bones, tail, cape);
  they follow their parent in their bind rotation unless an embedded clip moves them.
- Give hands, feet and head a child bone (fingers, toe, head tip): the loader uses
  it to measure the direction of that segment.
- Conventional names help the automatic map: `Hips`, `Spine`, `Chest`/`Spine2`, `Neck`,
  `Head`, `UpperArm_L`/`LeftArm`/`upper_arm.L`, `Forearm_L`/`LeftForeArm`,
  `Hand_L`, `Thigh_L`/`LeftUpLeg`, `Shin_L`/`LeftLeg`, `Foot_L`. Otherwise write `jointMap`.
- At most 4 bone influences per vertex, weights normalized.

**Budget (per fighter, measured with the test mannequin)**
- Test file: 954 vertices, 936 triangles, 26 joints, 3 materials, 1 texture, 65 KB.
  Parse 3.7 ms, build 5.6–9.8 ms (browser), retargeting 0.03 ms per frame,
  one afterimage bake 0.6 ms, 60 fps with two imported fighters.
- Suggested production budget: ≤ 20,000 triangles, ≤ 60 joints, ≤ 4 materials per fighter.
  Afterimages bake the skinned pose on the CPU and cost grows with vertex count
  (about 13 ms per afterimage at 20,000 vertices by extrapolation) — a lower-detail
  afterimage mesh will be needed at that size.

**Not carried over from procedural bodies yet**
- Hair swaps per form (Super Saiyan), facial expressions and blinking, hand shapes
  (fist / open), stretching limbs (Piccolo), capes and belt cloth springs. Each needs a
  model-side convention (mesh variants, morph targets or extra bones) before real
  character models can replace the procedural ones.
